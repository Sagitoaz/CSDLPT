08 Sequence Create Donation With Payment

sequenceDiagram
    autonumber
    actor Donor
    participant FE as Frontend
    participant API as Backend API
    participant Camp as Campaign Service
    participant Donate as Donation Service
    participant Pay as Payment Service
    participant DB as MongoDB PRIMARY / mongos
    participant SEC as SECONDARY nodes

    Donor->>FE: Fill donation form
    FE->>API: POST /api/donations
    API->>API: Validate donorName, donorEmail, amount, campaignCode
    API->>Camp: Check campaignCode, isActive, date range
    Camp->>DB: find campaigns by code
    DB-->>Camp: Campaign + branchCode
    API->>Donate: Create donation status = pending
    Donate->>DB: insert donations with campaignCode and branchCode
    DB-->>SEC: Replicate oplog
    API->>Pay: Create payment transaction status = pending
    Pay->>DB: insert payment_transactions
    DB-->>SEC: Replicate oplog
    API-->>FE: 201 Created + payment instruction
    FE-->>Donor: Show pending donation and payment info

09 Sequence Payment Callback Or Reconciliation

sequenceDiagram
    autonumber
    actor Provider as Bank/E-wallet/Cashier
    participant API as Backend API
    participant Pay as Payment Service
    participant Donate as Donation Service
    participant DB as MongoDB PRIMARY / mongos
    participant Audit as audit_logs

    Provider->>API: Payment callback / reconciliation result
    API->>Pay: Validate providerTxnId, amount, donationId
    Pay->>DB: update payment_transactions.status
    alt payment success
        Pay->>Donate: Mark donation ready for review or verified by policy
        Donate->>DB: update donation payment-related state
    else payment failed/refunded
        Pay->>DB: keep donation pending or mark payment failed
    end
    API->>Audit: log payment action
    Audit->>DB: insert audit_logs
    API-->>Provider: 200 OK

10 Sequence Review Donation

sequenceDiagram
    autonumber
    actor Staff as Staff / Branch Admin / System Admin
    participant FE as Admin Frontend
    participant API as Backend API
    participant RBAC as JWT + RBAC
    participant Donate as Donation Service
    participant DB as MongoDB PRIMARY / mongos
    participant Stats as Stats Aggregation
    participant Audit as audit_logs

    Staff->>FE: Choose verified or rejected
    FE->>API: PATCH /api/donations/:id/status
    API->>RBAC: Check role and branchCode scope
    RBAC-->>API: Allowed
    API->>Donate: Validate status transition
    Donate->>DB: update donation status, reviewedBy, reviewedAt
    Donate->>Stats: Recalculate verified totals
    Stats->>DB: aggregate donations where status = verified
    API->>Audit: log review action
    Audit->>DB: insert audit_logs
    API-->>FE: 200 OK

11 Campaign Report Workflow

stateDiagram-v2
    [*] --> draft: Staff creates report
    draft --> submitted: Submit report
    submitted --> approved: Branch admin or system admin approves
    submitted --> rejected: Branch admin or system admin rejects
    rejected --> draft: Staff edits and resubmits
    approved --> published: Publish to donor/public view
    published --> [*]

15 Integrity Rules Flow

flowchart TB
    INPUT["Client request"] --> VALIDATE["Zod / DTO validation"]
    VALIDATE --> RBAC["JWT + RBAC + branchCode scope"]
    RBAC --> REF["Reference checks<br/>campaignCode exists<br/>donationId exists<br/>branchCode valid"]
    REF --> ENUM["Enum checks<br/>role, donation status,<br/>payment status, report status"]
    ENUM --> DB[("MongoDB indexes + writes")]
    DB --> AUDIT["audit_logs for important actions"]
    DB --> REPL["Replica Set replication"]

    BAD1["Invalid amount/email/date"] -. reject .-> VALIDATE
    BAD2["Cross-branch access"] -. reject .-> RBAC
    BAD3["Missing campaign/donation"] -. reject .-> REF
